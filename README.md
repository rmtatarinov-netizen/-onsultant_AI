# Konsultant_AI — два Telegram-консультанта по страхованию

Два независимых бота на aiogram 3 + OpenAI-совместимом API:

- `bot_short.py` — **короткая память**: последние N пар сообщений в RAM, долгосрочного
  хранилища нет, после рестарта контекст исчезает.
- `bot_long.py` — **длинная память**: история и тезисы в SQLite, при запуске тезисы
  загружаются из базы и добавляются в системный промпт.

Оба бота получают от модели **один JSON-объект** с двумя ключами в порядке
`тезисы` → `message`. В чат уходит только `message`, тезисы пишутся в консоль
(логгер `theses`) и, в режиме `long`, сохраняются в SQLite.

## Структура

```
app/config.py           токены, модель, SYSTEM_PROMPT, доменный промпт, инструкция JSON
app/logging_config.py   настройка логов и логгер theses
app/db.py               SQLite: таблицы dialogue_messages и theses, WAL, обрезка старых записей
app/memory.py           ShortMemory (deque) и LongMemory (SQLite)
app/llm.py              strict JSON Schema, разбор ответа, fallback на plain text
app/handlers.py         /start, /help, /memory, /reset, обработка текста
app/bot.py              сборка зависимостей и long polling
tests/                  pytest с подставным OpenAI-клиентом (без реальных вызовов)
```

## Запуск

1. Скопируйте `.env.example` в `.env` и задайте **два разных токена** от BotFather
   (`BOT_TOKEN_SHORT`, `BOT_TOKEN_LONG`), ключ и base URL API.
2. Запустите оба контейнера:

```powershell
docker compose up --build -d
docker compose logs -f short
docker compose logs -f long
```

База длинной памяти лежит в именованном volume `bot-data` по пути
`/app/data/consultant.db`; короткий бот использует `/tmp/short.db` и ничего не сохраняет
между перезапусками.

Локальный запуск без Docker:

```powershell
python -m pip install -r requirements-dev.txt
$env:BOT_TOKEN = "..."; $env:OPENAI_API_KEY = "..."
python bot_short.py
python bot_long.py
```

Для structured output нужна модель с поддержкой `response_format: json_schema`
(`gpt-4o-mini`, `gpt-4o-2024-08-06` и др.). Если провайдер её не поддерживает,
код не падает: ответ воспринимается как обычный текст, тезисы пустые.

## Команды

| Команда | Действие |
| --- | --- |
| `/start` | Приветствие и описание режима памяти |
| `/help` | Краткая справка |
| `/memory` | Сколько тезисов сохранено (в `short` всегда 0) |
| `/reset` | Принудительная очистка контекста: deque в RAM или строки в SQLite |

## Формат ответа модели

```json
{
  "тезисы": ["Пользователь хочет застраховать жизнь", "Клиент интересуется накоплениями"],
  "message": "Для защиты семьи обычно рассматривают страхование жизни..."
}
```

Схема передаётся через `response_format={"type": "json_schema", "strict": true}`;
порядок свойств в схеме — `тезисы`, затем `message`. `message` отправляется в чат,
`тезисы` логируются:

```text
2026-... | INFO | theses | user_id=1 mode=long тезисы: ["Пользователь хочет застраховать жизнь"]
```

## Сценарии сравнения

1. В обоих ботах: `/start`, затем «Меня зовут Саша, я хочу застраховать жизнь и
   накопить ребёнку». Проверьте в консоли строки логгера `theses`.
2. Спросите «Какие мои планы?». Оба бота отвечают по контексту текущего сеанса.
3. `docker compose restart long` и `docker compose restart short`, затем повторите
   вопрос. **long** помнит намерение (тезисы подставлены в system-промпт из SQLite),
   **short** начинает с чистого листа.
4. Отправьте больше 10 пар вопросов/ответов. **short** вытесняет самые старые,
   **long** хранит историю и до 30 последних тезисов на пользователя.
5. `/reset` в long, затем тот же вопрос: бот больше не опирается на старые тезисы;
   проверьте, что таблицы пусты: `docker compose exec long python -c "import sqlite3; ..."`.
6. `/memory` до и после сброса — счётчик сохранённых тезисов.

## Результаты сравнения

| Критерий | Короткая память | Длинная память |
| --- | --- | --- |
| Реализация | deque в RAM, минимум кода | SQLite + загрузка тезисов при старте |
| Переживает рестарт | Нет | Да |
| Реакция на «Какие мои планы?» | Только в рамках последних пар, иначе переспрашивает | Продолжает с учётом «Саша хочет …» |
| После `/reset` | История очищена сразу | Очищаются история и тезисы в БД |
| Риски | Теряет давний контекст | Нужны лимит тезисов и очистка, иначе промпт растёт |

Вывод: короткая версия проще и предсказуемее, но для страхового консультанта
практичнее длинная — она не заставляет клиента повторять детали после рестарта
и лучше ведёт диалог по накопленному контексту.

## Проверки

```powershell
ruff check .
ruff format --check .
python -m pytest
```

Тесты проверяют вытеснение старых сообщений, восстановление тезисов из SQLite после
«перезапуска», подстановку тезисов в промпт, `/reset`, порядок ключей JSON, fallback
и то, что тезисы попадают в логи, но не в ответ чата.
